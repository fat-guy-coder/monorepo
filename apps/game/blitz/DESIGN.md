> **当前版本：v0.4（2.5D 横版 / belt-scroll，DNF 那个维度）。**
> 本文件是**设计与技术现状**的权威文档；本轮换视角的来龙去脉、逐步实施记录、两道闸门和踩过的坑，

> 核心体验：**御剑问道，快意恩仇。** 在 2.5D 横版的仙侠世界里，用高频操作和丰富技能构筑，
> 一步步探索、变强、揭开故事。
> 一句话：**暗黑式的刷装备 + 怪猎式的固定分图 + 低惩罚死亡 + 大表哥式对话推剧情。**

## 一句话定位

**2.5D 横版**（belt-scroll）仙侠动作 RPG。地面有 **X（左右）+ Z（纵深）两条轴**，朝向**只分左右**，
跳跃是一个真正的战术维度（Y 高度）。

玩家在**固定地图**（分块加载）里探索，打怪掉落**永久装备/技能**，死亡在**复活点**复活（低惩罚），
通过**触发 NPC 对话**推进剧情。战斗偏动作向：高频操作、强反馈、技能丰富，让玩家有多种方式打怪。

## 为什么是「2.5D 横版」，而不是等距 / 真 3D

这一节是**用两轮实测换来的结论**，不是拍脑袋。走错的那一轮值得完整记下来。

### 走过的路

| 版本 | 视角 | 结果 |
|------|------|------|
| v0.1 | 2D 横版**平台跳跃** | 只有左右 + 跳，没有纵深走位，探索感太薄 |
| v0.2–v0.3 | **等距** 3/4 | 美术看起来好，但**操作和地面在说两种语言**：按 W 走直线，脚下的地砖却是斜的，怎么走都错开半格 |
| **v0.4 ✅** | **2.5D 横版（belt-scroll）** | 地面两轴与输入天然一致；朝向只有左右，美术成本最低 |

### 等距错在哪（不是八向输入的问题）

等距的实现是「**屏幕 XY 就是世界 XY**，只在 `_draw()` 里把地面压扁画成菱形」。
于是：

- 输入 `Input.get_vector(...)` 直接是**屏幕横竖**；
- 地面网格的两根轴却是屏幕的**斜线**；
- 角色位置、速度、判定框全是未投影的屏幕坐标。

**「输入映射到等距轴」这件事在 Model A 下根本做不到** —— 两种坐标系从来没有统一过。
表现就是「跟野怪对不上」：你觉得对着它，判定框却偏在一边。

### 纠正 v0.2 写下的两个错误论据

| v0.2 当时的说法 | 事实 |
|---|---|
| 「2D 横版只有左右 + 跳，装不下 XY 平面走位」 | 那是**平台跳跃**版横版。**belt-scroll**（DNF / 三国战纪 / 怒之铁拳）有 **X + Z 两条地面轴**，平面走位一直都在，只是轴名叫「左右 + 纵深」 |
| 「真 2.5D 要 4-8 方向资产，solo 扛不住」 | belt-scroll 的**朝向只分左右**，美术 **2 组**（朝右 + 镜像），比等距八向**便宜 4 倍**。等距才是那个需要八向资产的方案 |

### 为什么不是真 3D

建模 / 绑骨 / 贴图 / 动画 / 光照是三条路线里最贵的，且偏离「纯 2D 手绘」的美术规划。
2.5D 横版用「纯 2D 精灵 + 纵深压缩 + Y-sort」拿到立体的观感，成本是 3D 的零头。

### 代价（诚实地写下来）

- **深度遮挡比等距弱**：只有前后，没有「左后被墙挡住」这类构图。
- **Z 轴的表现力有限**：纵深是「可以站的一行行」，不是自由移动的平面。这与「每个招式自带形状、范围在 XZ 平面上」的判定模型正好匹配。
- **大地图探索还没想清楚**：先用「城镇 + 房间副本」的房间制装下（见下节）。

## 坐标模型（整个项目的地基）

```
世界 = 3 个数:  x (左右)   z (纵深)   height (离地高度)
引擎里存:      global_position = Vector2(x, -z)        ← 纵深吃负 Y
屏幕显示:      y_screen = -z × DEPTH_SCALE (0.5)       ← 纵深压扁一半
高度:          height 单独一个标量, 只用在 _draw() 里
```

三个白送的好处：

1. **Y-sort 一行不用改** —— 「屏幕 Y 越大越靠前」正好就是纵深排序。
2. **重力只作用在 `height` 上，永远不碰 `position.y`** —— 这条是铁律。写成
   `velocity.y += gravity * delta` 角色会一边跳一边往屏幕深处漂；Y-sort 也会按抬起来之后的
   y 排序，一跳就钻到别人后面。**能跑、能跳、看起来也对，所以是静默 bug。**
3. **跳跃是纯加法** —— 身体画在「脚底 + (0, -height)」，影子留在脚底。现有「原点在脚底」的
   约定天然兼容。

**唯一桥：** [scripts/belt_space.gd](scripts/belt_space.gd)（`to_screen` / `to_world` /
`ground_circle` / `ground_circle_shape` / `limit_world_speed`）。任何别处自己手写投影数学，
都是在制造第二个真相。

## 核心循环

```
探索地图 → 打怪 → 掉装备/技能/资源 → 变强 → 推进地图 → 触发剧情
     ↑                                              │
     └────────── 死亡 → 复活点复活（低惩罚）────────┘
```

- **死亡不重开**（非肉鸽）：死亡 → 在最近的复活点复活，已获得的装备/资源**永久保留**
- **死亡惩罚低**（具体待定）：倾向「掉一点资源/经验」而非「掉装备」，避免挫败
- **地图固定**：不做随机地图，玩家按顺序探索一张张分块地图
- **资源是仙侠的灵魂**：修为、灵石、丹药、装备、功法都是可积累的资源

## 地图结构（怪猎式分块 · 暂定房间制）

| 特性 | 说明 |
|------|------|
| 结构 | 世界由**多张固定小地图**组成，进入边界触发加载切换到下一张 |
| 连接 | 类似怪猎/黑魂——地图间有明确连接点（山道、洞口、传送阵） |
| 复活点 | 每张地图设 1-2 个复活点（蒲团/石碑/阵眼），死亡在此复活 |
| Boss 区 | 关键地图设 Boss 房，进门即战 |
| 探索节奏 | 固定但非线性——部分地图可解锁捷径回环（回到已探索区） |

> ⚠️ **大地图探索的具体形态还没拍板**（用户原话：「还没想清楚」）。v0.4 只保证
> 「城镇 + 房间副本」的房间制**装得下**，不提前锁死结构。
>
> 设计原则：**小地图 + 明确连接 + 回环捷径**，让玩家「一个个探索」有进度感，又不用做无缝大世界。

## 战斗系统（动作向）

### 目标：高频操作 + 强反馈 + 有挑战性

玩家需要频繁做决策（打 / 躲 / 挡 / 跳 / 放技能），每一次操作都有明确的即时反馈。

### 基础操作（v0.4 实装值）

| 操作 | 按键 | 说明 |
|------|------|------|
| 移动 | WASD / 方向键 | **X（左右）+ Z（纵深）** 两条地面轴 |
| 跳跃 | **C** | 重力 1400 / 起跳速度 520 / 满跳高度 ≈96.6；可变跳跃高度（松键截断） |
| 轻击 | J / 鼠标左键 | 扇形扫击，伤害 1，硬直 0.15s |
| 重击 | **按住** K / 鼠标右键蓄力，松开挥出 | 0.75s 蓄满；伤害 2→4；**满蓄破霸体** |
| 技能（落雷） | U | 身前一格半处圆形 AoE，**延迟 0.38s 生效**（能走出去） |
| 闪避 | Space | 无敌帧冲刺，消耗精力 25 |
| 格挡 | **按住** Shift / L | **前后半平面**免伤（只看 X 的符号，纵深不参与），持续耗精力 + 每次硬挡扣 20 |
| 精准格挡 | 按下格挡键的**那一瞬间**（0.16s 窗口） | 零伤零耗 + 攻击者硬直 1.2s（反击窗口） |
| 调试面板 | F1 | 范围可视化 / 纵深泳道 / 按键 |
| 重开 | R / Enter | 开发期用 |

### v0.4 的操作规则（v0.3 的三条里有一条被删了）

1. **朝向只由左右输入决定。** 只按上下（纵深）**不转身** —— 横版没有「朝上」这个状态。
2. **格挡只挡面朝的那一侧，但纵深方向一律算正面。**
   > 这正是用户要的效果：「站得比我靠前/靠后一点，攻击一样得挡得住」。
   > 判定只看 `dx` 的符号，一次比较，**没有可以调窄的旋钮**。
3. **格挡有 0.45s 的精准窗口冷却。**
   > 没有它的话最优解是疯狂连点 Shift，每一下都重开窗口 ——「精准格挡」退化成没有代价的按键宏。
4. **蓄力时可以 50% 速度慢走**（不是原地定身）。
   > 定身会让蓄力在走位为主的战斗里几乎用不出来 —— 敌人一起手你就必须走。

> **被删掉的一条：** v0.3 的「格挡时朝向跟随鼠标」。
> 它不是手感问题，是**等距逼出来的补丁**：朝向只在移动时更新，那么「站着举盾 → 敌人绕到背后」
> 就必然无解。横版里朝向只有左右，鼠标在角色正上方时该朝左还是朝右**没有答案** ——
> 这个补丁连同 `block_aim_override` 出口一起删掉了。

### 资源系统

| 资源 | 上限 | 恢复 | 用途 | 设计意图 |
|------|------|------|------|----------|
| 生命 HP | 成长（当前 3） | 药品/复活点/修为 | 归零死亡 | 生存压力 |
| 精力 (Stamina) | 固定 100 | 每秒 45，消耗后停 0.7s | 闪避/重击/格挡消耗 | **驱动高频决策**——魂系式资源管理 |
| 真气/灵力 (Mana) | 成长 | 缓慢恢复/击杀 | 技能/法术消耗 | 技能使用的节奏（未实装） |

> 精力系统是「操作频率高」的关键：闪避要耗精力，逼玩家在「躲/打/等精力」之间快速切换，而不是无脑翻滚。

### 攻击范围 = 每个招式自带一个形状（v0.4 核心机制）

用户的原话（仍然是验收标准）：

> 「范围攻击就是在 x 和在纵深轴画一个范围，可以是圆形（应该是椭圆形更准确）、扇形，矩形。
> 比如横劈动作就是一个扇形，扇形区域内的敌人或者玩家（敌人发起的动作）会受到伤害。
> 可以做一个横批的攻击（敌人也做上），再给玩家来一个技能，可以在玩家面朝方向一定距离的圆形
> （视角内椭圆形？）造成伤害，就是闪电从空中落下然后在区域内造成伤害」

> 「敌人的攻击可以是一个横向轴的单独判断，也可以是一个范围工具，就是在它的攻击范围内，
> 离他几根横向轴上都会收到攻击」

实装为 [scripts/combat/attack_shape.gd](scripts/combat/attack_shape.gd)（`AttackShape`，`Resource`）：

| 形状 | 用法 | 当前实例 |
|------|------|---------|
| `RECT` | 身前一条窄而远的长条 | 玩家重击：长 96 × 纵深 52 |
| `ARC` | 贴着身扫一片（半径 + 张角） | 玩家横劈：r=66 / ±75°；**敌人横扫：r=54 / ±60°** |
| `CIRCLE` | 一个点周围的圆（可带偏移） | 落雷：r=46，圆心在身前 132 处 |
| `band(min, max)` | 叠加**离地高度带** | 敌人横扫：`band(0, 40)` —— 跳过去就躲得开 |

三条与形状绑定的不变量（**改了会静默出错**）：

1. **一招 = 一个 `AttackShape` 实例。** 起手预警、`CollisionShape2D`、自检读的都是它 →
   「地上画的范围」和「真的会打到你的范围」在结构上不可能漂移。
2. **`origin` 永远是攻击者的脚底。** 形状自己的 `offset` 决定圆心在哪，物理体的
   `collision_offset(facing)` 决定碰撞体中心。**两处都偏 = 偏两次。**
3. **靶子的碰撞体必须活在地面平面上**（`BeltSpace.ground_circle_shape`）。
   用 `CircleShape2D` 的话，屏幕正圆在地面平面里是一个**纵深翻倍**的椭圆 ——
   表现是「站在扇形外面一格半照样掉血」。

### 敌方的攻击形状

敌人横扫 = 低空扇形。**高度带是加跳跃的主要收益**：没有它，跳跃在地面战斗里只是一个好看的位移。
判定点放在**受击方**（Area2D 活在 2D 平面，表达不了离地高度）：

- 敌人打玩家 → 玩家的 Hurtbox 用自己的 `height` 查；
- 玩家打敌人 → `AttackHitbox._try_hit` 读敌人 body 的 `height`。

两条链路对称，都由「谁受伤谁查」这条老约定控制。

### 技能系统（核心卖点：多种方式打怪）

**目标：让玩家构筑自己的打法。** 分三层：

1. **招式（近战武学）**：剑法/刀法/枪法等，改变轻击重击的连段和效果
2. **法术（远程/控制）**：飞剑、剑气、符箓、阵法——远程伤害、AOE、控场
3. **法宝（特殊机制）**：主动释放的强力道具，如飞剑自动索敌、护体罡气、瞬移

| 层 | 举例 | 对应打法 |
|----|------|---------|
| 招式 | 快剑（攻速快）/ 重剑（高伤破防）/ 枪（长手范围）| 近战流派 |
| 法术 | 飞剑索敌 / 剑雨 AOE / 定身符 | 远程/风筝流派 |
| 法宝 | 护体罡气 / 影分身 / 御剑飞行 | 特殊玩法流派 |

> **构筑逻辑**：装备决定「招式」和基础数值，技能槽位（主动）+ 词条（被动）决定「怎么打」。
> 同一套装备 + 不同技能 = 不同打法。**用少量装备 × 大量技能组合，代替几百件装备**，解决内容消耗问题。
>
> 每个新技能在代码里就是一个**新的 `AttackShape` 组合**（形状 + 偏移 + 高度带 + 延迟），
> 不需要新的判定框架。

## 剧情系统（大表哥式对话推进）

- 剧情通过**触发 NPC 对话**推进，不做强制过场
- 玩家自由探索，走到关键 NPC/地点触发对话，推进主线
- 对话中可解锁新地图、新技能、新任务
- 结构：**主线（关键 NPC）+ 支线（世界里的散落 NPC/事件）**

> 设计要点：剧情是「探索的奖励」而非「强制引导」。玩家想推剧情就去找 NPC，想刷装备就继续打怪，自由度归玩家。
>
> 实现倾向：对话系统是**商品化基础设施**，届时应直接采用社区标准件（Dialogue Manager 3，nathanhoad，MIT），
> 不手写 —— 手写它没有学习收益，只有成本。

## 技术实现（Godot 4.6）

### 视角与渲染分层

| 技术点 | 实现 |
|--------|------|
| 地面 | `belt_floor.gd` 程序化平铺条带（不是 TileMap / TileSet） |
| 角色 | `_draw()` 侧视几何占位（朝向 ±1，左右镜像） |
| 纵深压缩 | 世界 z → 屏幕 y × 0.5（`BeltSpace.DEPTH_SCALE`） |
| 深度排序 | `y_sort_enabled = true` —— 屏幕 Y 就是纵深 |
| 移动 | X + Z 两轴独立，速度用**世界单位**、上限在世界空间截断 |
| 碰撞 | `CharacterBody2D` + 贴地椭圆（`ConvexPolygonShape2D`） |
| 攻击判定 | 短命 `Area2D` + `AttackShape` |
| 摄像机 | `Camera2D` 跟随 + 从地面推导边界 + trauma 震屏 |

**图层顺序（绝对 `z_index`，先于 y-sort 结算）：**

```
Backdrop(-20) < Floor(-10) < 贴地预警 GroundTelegraph(-5) < 角色/刀光(0) < Fx(40)
```

> ⚠️ 贴地层必须 `z_as_relative = false`。开着的话 `z_index` 相对父节点结算，
> 而父节点在 0 —— 减出来还是 0，**静默失效**。
>
> 起手预警必须垫在角色**下面**：玩家要看的是「**我的脚**在不在里面」，被身体盖住的正是最关键的那块。
> 命中帧的闪光则故意留在角色层（要看「谁从哪边打的我」）。

**碰撞层（bit 定义，全项目一致）：**

| bit | 用途 |
|-----|------|
| 0 | 玩家身体 |
| 1 | 敌人身体 |
| 2 | 玩家攻击 |
| 3 | 敌人攻击 |
| 4 | 墙壁 / 障碍 |
| 5 | 交互物 / 复活点 |

### 打击感四要素（0 素材成本）

| 要素 | 做法 | 成本 |
|------|------|------|
| 屏幕震动 | Camera2D offset Tween，重击 4px 轻击 1px | 0 |
| 击停帧 | 命中瞬间双方暂停 0.05-0.1s | 0 |
| 粒子特效 | 命中火花、剑气拖尾、受击碎片 | 0（程序化） |
| 音效 | 挥剑/命中/格挡/死亡声 | 需素材 |

- **场景/坐标**：装配 · 相机边界 · 障碍碰撞体非零 · 边界墙拦人 · 坐标桥往返 · 压扁比 2:1
- **高度轴**：按跳能离地 · 重力**不改** `global_position.y` · 落地 height 精确归零 · 受击不能跳 · 纵深输入不转身
- **形状**：RECT 纵深边界 · ARC 角度与纵深容差（随位置变化，不是常数）· CIRCLE 偏移 · 高度带 · 玩家横劈纵深比敌人更宽
- **战斗**：格挡正面免伤 / 背后掉血 / 纵深算正面 · 精准窗口（命中/过期/自动关闭）· 举盾不改朝向 · 破防门槛 · 蓄力破霸体 · 霸体不被打断 · 蓄力中受击不卡死

**全部通过退出码 0，有失败退出码 1。**

### 人工验收（自检证明不了，必须 F5）

1. **横向对得上了吗** —— 按 D 向右走，脚下地砖跟人一起动、不再斜着错开
2. **跳跃读得出来吗** —— 起跳/滞空/落地三阶段，影子有没有留在原地当参照
3. **攻击范围看得见吗** —— 敌人起手时地上那片扇形，是不是一眼就知道该站哪（它必须画在角色**下面**）
4. **纵深容差合适吗** —— 站在敌人上下一点点，该中招吗？会不会太宽容
5. **跳跃躲得开吗** —— 跳起来躲低扫，是不是个有意义的操作
6. **精准格挡有回报感吗** —— 金色爆闪 + 敌人硬直，是不是立刻想反打
7. **精力逼出取舍了吗** —— 是否出现过「想闪但精力不够」的时刻
8. **破防够痛吗** —— 精力见底被打崩，是否让你下次不敢硬挡

## 设计原则

1. **玩法第一** — 手感调好了再加美术和内容
2. **纯代码先行** — 原型不需要外部素材，`_draw()` 几何图形验证
3. **资源是灵魂** — 仙侠的爽点是「积累变强」，掉落和成长要做好
4. **操作高频 + 反馈强** — 精力系统 + 打击感 > 招式数量
5. **少装备多组合** — 用技能构筑代替海量装备，省内容
6. **可测试** — 任何时候 F5 都能跑；自检 + 截图探针是两道自动化闸门
7. **边做边写文档** — 脚本标注学习文档引用，双向关联
8. **画的就是判的** — 一切范围必须同源（一个 `AttackShape`），禁止两处各算一遍
