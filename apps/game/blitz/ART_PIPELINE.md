# Blitz 美术资产生产流程（2D 像素 · 个人开发者）

> **目标**：一个人做出「像素、但精美、动作多、风格统一」的 2.5D 横版 ARPG。
> 参照系是 Dead Cells 的精致度，规模可以小一档（否则素材量不可能一个人扛）。
>
> 本文档是**操作手册**：每一步产出什么、用什么工具、参数怎么设、验收标准是什么。
> **路线选型（逐帧像素 vs 3D 预渲染）的决策依据见 [ART_ROUTE_DECISION.md](ART_ROUTE_DECISION.md)。**
> 设计层面的取舍见 [DESIGN.md](DESIGN.md)；视角与坐标模型见同文件「坐标模型」一节。

---

## 0. 先读这一节：Dead Cells 的真相

Dead Cells 的角色**不是手绘逐帧像素画**。Motion Twin 用的是 **3D 模型 + 像素化渲染**：
3D 资产负责动作（骨骼、物理、布娃娃），像素化 shader 负责观感。所以它能以很小的团队
做出几十种敌人、上百种动作、换武器换皮肤几乎零成本。

这句话有两个直接含义：

1. **「像素」是渲染结果，不是生产方式。** 想要 Dead Cells 那种动作量，逐帧画是画不完的。
2. **反过来，如果只追求「看起来是像素」**，手绘/AI 逐帧在单个角色、少量动作上是完全可行的，
   而且风格上限可以更高（更有手绘味）。

### 两条路线，先选一条再开工

| | **路线 A：逐帧像素** | **路线 B：3D 渲像素** |
|---|---|---|
| 做法 | AI 生成底图 + Aseprite 手修，导出精灵表 | Blender 建模/绑骨/动画 → 正交侧视渲成序列帧 |
| 动作量上限 | 低（一帧一帧画，一个角色 30~50 帧） | 高（动作是数据，可无限复用、可混合） |
| 换装/换武器 | 重新画 | 换材质/模型，几秒 |
| 风格上限 | 高（手绘感强） | 中高（Dead Cells 就是这条路） |
| 前期投入 | 低，一天能看到画面 | 高，要学 Blender 管线（1~2 周） |
| 长期成本 | 线性增长（角色/动作越多越贵） | 边际成本低（角色越多越划算） |
| 适合 | 角色 ≤ 2、动作 ≤ 10 的原型/小体量 | 完整游戏、多敌人、多武器 |

**判断标准**：
- 只是想先把 Blitz 的画面做「像样」→ 走 A。
- 目标是完整商业作品、敌人 ≥ 3、每个角色动作 ≥ 10 → 走 B，越早越好。

> **建议的折中**：先用路线 A 做一个**垂直切片**（1 周内看到画面，快速验证观感和尺寸），
> 同时用路线 B 做**第二个角色**做对比。两条都摸过一遍再决定继续哪条 —— 不要在第一天锁死。
>
> Blitz 的角色朝向只有 ±1，路线 B 只需要**一个正交侧机位**，是 3D 渲像素里最省的一种。

## 1. 第一步到底产出什么：风格锚

先回答一个容易混淆的问题：

> 「先去 Midjourney / Flux 定义风格」这一步，是生成 Skill，还是生成地图？

**都不是。** 它不产出任何游戏可用资产，也不产出地图。它产出的是 **风格锚（style bible）**：
一组「以后所有美术都必须符合」的约束。地图/场景是后面独立的阶段。

风格锚的实体是一个目录：

```
apps/game/blitz/art/style_bible/
├── references/            3~5 张参考图（选定的风格定稿）
├── palette.gpl            Aseprite 调色板（16 / 32 / 48 色，见下）
├── rules.md               像素密度、头身比、光照方向、描边规则、禁止项
├── prompts.md             正/负提示词模板、固定种子、参考图用法
└── character_sheet.png    主角三视图 / A-pose 基准图
```

**它和 Claude Code Skill 的关系**：风格锚本身不是 Skill。但如果你希望以后每次让 AI 生成资产
都自动遵守它，可以把上面这些文件包成项目 Skill（`.claude/skills/art-style/SKILL.md`，
内容是「生成任何 Blitz 美术前，先读 style_bible/ 下的 rules.md / palette.gpl / prompts.md」）。
Skill 只是**读取约束的包装**，风格本身仍然是那些文件。

### 定风格的操作步骤（1~2 天）

1. 用 Midjourney 或 Flux 生成 **20~30 张候选概念图**（不要求可用，只看方向）。
   - 关键词骨架：`pixel art, side view, 2.5D belt-scroll beat-em-up, wuxia, ...`
   - 要求：同一角色**正面/侧面/三分之四侧**各来几张。
2. 从中挑 **3~5 张**作为风格定稿，存进 `references/`。
3. 用 Aseprite 的「从图片建调色板」抽色，人工合并到 **32~48 色**（见下），存成 `palette.gpl`。
4. 写 `rules.md`，把下面这些数字**写死**：

| 项 | 建议值（Blitz） | 为什么 |
|---|---|---|
| 美术像素 = 屏幕像素 | 1:1（相机 zoom = 1，1280×720） | 不缩放就不会有像素抖动/糊边 |
| 角色高度 | 主角 96~112px，杂兵 72~96px | 当前占位只有 ~55px，撑不住「精美」 |
| 头身比 | 4.5~5 头身 | 横版动作游戏要能看清四肢 |
| 色数 | 32~48 色（不是 16 色） | 16 色是复古风；你要的是「精致」 |
| 描边 | 1px 深色外轮廓（不是纯黑，用深冷色） | 保证剪影在任何背景上都清楚 |
| 光照 | 固定左上光源 | 所有角色/场景统一，是风格一致的关键 |
| 抗锯齿 | **禁止** | 像素画里 AA 会糊掉网格 |
| 渐变 | 用色阶/抖动，不用平滑渐变 | 同上 |
| 地砖网格 | 32×32（Blitz 一格 64×32 = 2×1 块） | 兼容现有 `BeltFloor` 单元格 |

5. 把选定的提示词、负面词、种子写进 `prompts.md`（模板见第 3 节）。

## 2. 工具链选型

### 2.1 像素生成：Retro Diffusion vs PixelLab

| | **Retro Diffusion** | **PixelLab** |
|---|---|---|
| 定位 | 专训像素风的生成模型 + Aseprite 插件 + 在线生成器 | 面向游戏资产的像素生成器 |
| 强项 | 风格跨度大（NES/SNES/GBA/现代高分辨率）、调色板约束、场景与道具、精灵表/动画辅助 | 角色**多方向**生成、走路/攻击**动画生成**、等距素材、Aseprite 插件 |
| 弱项 | 多动作之间的角色一致性一般，动画仍需修帧 | 风格范围较窄，容易「同质化」；高分辨率细节弱于 RD |
| 更适合 | **静态美术主力**：角色基准图、场景、道具、UI | **动作草稿/方向图/杂兵量产** |

**结论（不玩虚的）：**
- **静态美术能力：Retro Diffusion 更强。**
- **动作与方向的一致性：PixelLab 更省事。**
- 两者都按订阅/点数计费，建议**各花一周试**，用同一个角色做同一套 idle/walk/attack 对比，
  再决定主力。不要同时长期订阅。

### 2.2 手改工具：Aseprite vs LibreSprite vs Pixelorama

| | Aseprite | LibreSprite | Pixelorama |
|---|---|---|---|
| 价格 | 约 $20（Steam / 官网） | 免费开源 | 免费开源 |
| 状态 | 活跃维护 | 2016 年从 Aseprite 的 GPL 版本分叉，之后基本停更 | 活跃维护（本身是 Godot 写的） |
| 核心能力 | 绘画/图层/帧/洋葱皮/调色板/精灵表导出 | **都有** | **都有** |
| 差在哪 | —— | 缺近几年新增的瓦片地图模式、脚本 API、性能与 bug 修复；批量导出更弱 | 某些细节不如 Aseprite 顺手，但功能覆盖已经够用 |
| 建议 | **主力工具，20 美元值** | 不推荐当主力 | **不想花钱就选它**，别选 LibreSprite |

> 一句话：**LibreSprite 的能力大约是 Aseprite 的 2016 年版**，画单个角色够用，
> 但瓦片地图、脚本批量处理、导出规范这些「做量」的能力都缺。要么买 Aseprite，要么用 Pixelorama。

### 2.3 国内可用的生产流（不依赖外币卡/特殊网络）

| 环节 | 国内方案 | 说明 |
|---|---|---|
| 风格/角色/场景底图 | **LiblibAI（哩布哩布）** | Flux / SDXL 在线生成 + **在线训练 LoRA** + 模型市场；有大量像素风 LoRA |
| 批量工作流 / ControlNet | **RunningHub** | 在线 ComfyUI，可导入工作流，跑 OpenPose / 线稿 / 批量出图 |
| LoRA / 模型补充 | **TusiArt 吐司** | 模型与 LoRA 社区，在线生成 |
| 概念图 / 氛围探索 | **即梦**（字节） | 出图质量好、上手快，但不适合做一致性生产 |
| 3D 底模（路线 B） | **腾讯混元 3D / Tripo 国内版 / Meshy** | 生成基础模型 → Blender 清理 |
| 像素手改 | **Aseprite（Steam）/ Pixelorama** | Steam 可直接购买 |
| 法线贴图（后期动态光） | **Laigter**（免费） | 给像素图生成法线，配合 2D 光照 |

> Midjourney / Retro Diffusion / PixelLab 需要外币支付或特殊网络，**不要把它们当唯一主线**。
> 国内主栈建议：**LiblibAI（生成 + 训 LoRA）+ RunningHub（ComfyUI 批量）+ Aseprite（手修）**。
> 这套能覆盖 90% 的需求，且工作流可复现。

## 3. 标准生产流程（8 步）

> 每一节的「验收」都要真的做，别跳过。像素画的返工成本主要来自「画完 20 帧才发现比例错了」。

### Step 0 — 风格锚（1~2 天）

见第 1 节。产出 `art/style_bible/`，之后**每一张图都拿它对照**。

### Step 1 — 主角基准姿势（1 天）

- 画布：**112×112**（主角），透明背景，脚底贴画布底边居中。
- 姿势：侧视 A-pose / 自然站姿，朝右，武器可见。
- 工具：Retro Diffusion 或 LiblibAI（Flux + 像素 LoRA）+ 固定种子；出 20~30 张，
  挑一张，**在 Aseprite 里把比例、描边、色阶修到 rules.md 的标准**。
- 这张图是**后面所有动作的母版**：服装结构、色阶、描边粗细、头身比都以它为准。

**验收**：缩到 1× 看剪影，能不能一眼看出「拿剑的侠客」；把背景换成纯白/纯黑/草地色，剪影是否都清楚。

### Step 2 — 关键姿势（key pose），不要直接生成整段动画

每个动作只做 **3 个关键姿势**：

| 动作 | 关键姿势 |
|---|---|
| 轻击 | 预备（剑后拉）→ **命中帧**（剑到最远）→ 收势（剑收回） |
| 重击 | 蓄力（重心后坐）→ 命中 → 收势 |
| 跳跃 | 蹲 → 起跳 → 滞空 → 下落 → 落地（5 个） |
| 受击 | 后仰 1 个（+ 1 个回正） |

- 用 **ControlNet OpenPose**（RunningHub / ComfyUI）把姿势锁死，或者自己画火柴人当参考。
- 同一角色、同一服装、同一调色板，**只改姿势**。这一步的一致性比细节重要。

**验收**：把 3 个 key pose 并排看，像不像同一个人的三个阶段？不像就重来，别往下补帧。

### Step 3 — 补中间帧（2~4 天/角色）

- 首选：AI 生成中间帧 → Aseprite 手修（**每一帧都要过一遍手**，AI 帧只当草稿）。
- 或者：直接在 Aseprite 里手绘中间帧（小尺寸下其实很快）。
- 动作游戏的关键帧分布：**命中前的「预备」帧要多、要慢；命中后的「收势」可以少而快**。
  这是打击感的一半（预备 —— 发 —— 收）。

**验收**：以最终 fps 播放，闭眼再睁眼，能读出「抬手 → 砍 → 收」三段。

### Step 4 — 调色板统一（0.5 天/角色，批量做）

- 把每一帧映射到 `palette.gpl`。Aseprite 的「颜色模式 → 索引」+ 调色板替换可以批量做。
- 检查：同一材质的亮/中/暗三阶是否每帧一致；描边颜色是否统一；光源方向是否都从左上。
- **不要用自动减色**（会破坏像素画的色阶关系），手动映射到已定的 ramp。

**验收**：把所有帧拼成一张图，眯眼看，颜色像不像同一套。

### Step 5 — 对齐与导出

- **基线**：所有帧的脚底在同一 y 像素（主角站姿脚底 = 画布底边）。
- **枢轴**：水平方向以身体中轴为准；武器可以出画，但脚不能。
- 命名：`<角色>_<动作>_<序号>.png`，例如 `player_attack_light_03.png`。
- 导出两种：
  - **每动作一张精灵表 + JSON**（Aseprite: Export Sprite Sheet → Data: Hash/Array）；
  - 或直接用 **Aseprite Wizard** 插件在 Godot 里导入 `.aseprite` 源文件。
- 源文件 `.aseprite` 放 `art/source/`，**不要**混进 Godot 的导入目录。

### Step 6 — Godot 导入

| 设置 | 值 |
|---|---|
| Filter | **Off**（最近邻） |
| Mipmaps | **Off** |
| Compress | **Lossless**（像素图不要有损） |
| Project Settings → Rendering → Textures → Default Texture Filter | **Nearest** |

- 角色用 `AnimatedSprite2D` + `SpriteFrames`；一次性动作（攻击/受击/死亡）用
  `animation_finished` 或自己的状态机计时驱动，**不要依赖动画长度**。
- `flip_h` 管朝向；**只做朝右一套**。
- 跳跃：精灵层（不是角色节点）`position.y = -height`，影子留地面 —— 与现有 `_draw()` 的约定一致。

### Step 7 — 战斗时序对齐（**动作游戏最重要的一步**）

美术帧数不是美术定的，是**由战斗数值反推**的：

```
帧数 = 动作时长 × 播放 fps
命中帧时刻必须 = AttackHitbox 生成的时刻
```

当前 Blitz 的数值还太短，撑不住动画（轻击总共 0.15s = 24fps 下不到 4 帧）。
接真美术时建议同步调整（改完必须 F5 复核手感）：

| 动作 | 现在 | 建议（动画版） | 命中帧 |
|---|---|---|---|
| 玩家轻击 | 0.15s | **0.28~0.32s** | 第 4 帧 / 24fps（≈0.17s） |
| 玩家重击 | 0.34s | **0.45~0.55s** | 第 7 帧 / 24fps（≈0.29s） |
| 敌人起手 | 0.55s | 保持（13 帧 / 24fps） | —— |
| 敌人命中帧 | 0.14s | 保持（3~4 帧） | 第 1 帧 |
| 敌人收招 | 0.65s | 保持（15 帧 / 24fps） | —— |

**验收**：在调试面板里同时打开命中帧高亮和攻击范围，两者必须同一时刻出现。
建议给自检加一条「命中帧时间 ≈ 判定框生成时间」的断言（现在自检不依赖美术，加了更稳）。

### Step 8 — 集成验收

1. **1× 剪影测试**：不放大，站在地砖上，能不能一眼看出是什么角色/在做什么动作。
2. **三帧测试**：任意动作截 3 帧，动作方向是否可读。
3. **循环接缝**：idle/walk 的首尾帧是否衔接（最后一帧不能等于第一帧，否则会卡顿）。
4. **对齐**：跳跃时脚是否离开地面、影子是否留在原地；攻击时武器是否从身体正确的一侧出。
5. **朝向**：`flip_h` 后武器/披风是否还在合理的一侧（不对称设计会暴露镜像问题）。
6. **和判定的关系**：视觉范围与 `AttackShape` 的预警是否一致（预警是 UI，保持矢量，不要像素化）。

## 4. 帧预算（一个角色要画多少）

| 动作 | 帧数 | fps | 说明 |
|---|---|---|---|
| idle | 6 | 8~10 | 呼吸/衣摆 |
| walk | 8 | 12 | 两只脚各一个循环 |
| 轻击 | 6~7 | 24 | 含预备/命中/收势 |
| 重击 | 9~11 | 24 | 蓄力姿势可以复用 |
| 跳跃 | 5 | 不循环 | 蹲/起跳/滞空/下落/落地 |
| 受击 | 2 | 24 | 可以用程序位移补表现 |
| 死亡 | 5~6 | 12 | 最后碎成粒子（已有 `death_burst`） |
| 闪避 | 3~4 | 24 | 拖影可以用 shader |
| **合计** | **45~55** | | 主角 |

敌人：idle 4 / walk 6 / 起手 8 / 命中 4 / 收招 6 / 受击 2 / 死亡 6 ≈ **36 帧**。

> 一个人做完整游戏，**主角 50 帧 + 敌人 35 帧 × N** 就是总量。按上面的流程，
> 熟练后一个敌人约 3~5 天，主角约 2~3 周。

## 5. 复用策略（一个人做量的关键）

1. **镜像**：所有动作只做朝右。→ 直接省 50%。
2. **调色板换色**：同一套敌人帧，换调色板 = 新敌人（哥布林/骷髅/精英）。
   Aseprite 里用索引色模式 + 调色板替换，一次换一整套。
3. **共用特效**：刀光、命中火花、尘土、死亡碎片 —— 全游戏一套，按元素换色。
4. **共用受击/死亡帧**：体型相近的敌人可以复用，只换配色和武器。
5. **部件复用**：路线 B 下换武器/护甲是换模型部件；路线 A 下可以把武器单独拆一层
   （`weapon` 作为独立 Sprite，跟着手部锚点走），这样换武器不用重画身体。
6. **场景模块化**：地砖/墙/装饰各自一套 32×32 网格，靠组合而不是靠画大图。

## 6. 场景 / 地图管线

| 项 | 做法 |
|---|---|
| 地砖网格 | **32×32**；Blitz 的一格 64×32 = 2×1 块地砖 |
| 地面 | 2~3 种基础砖 + 边缘/转角自动拼接（Godot `TileMapLayer` 的 terrain 功能） |
| 背景 | 2~3 层视差条带（远景山/中景建筑/近景雾），层高按 128 或 256 的整数倍做 |
| 装饰 | 64×64 / 128×128 的独立 Sprite，参与 Y-sort |
| 光照 | 先**烘焙进像素**（左上光源）；后期要动态光再加 `Laigter` 法线贴图 |
| 与现有代码的接缝 | `BeltFloor` 的 `bounds_global()` / `cell_of()` 接口保留，只把 `_draw()` 换成贴图绘制或 `TileMapLayer` |
| 碰撞 | 场景美术和碰撞体分离，碰撞仍用现在的矩形墙/障碍逻辑 |

> 地面不要用「一张大图」，用可平铺的 32×32 砖 + 边缘过渡。大图在 2560 宽的关卡里会重复得很明显，
> 也没法做自动拼接。

## 7. 特效管线

| 特效 | 做法 | 复用 |
|---|---|---|
| 劈砍刀光 | 3~5 帧精灵，按元素换色；或用现有 `AttackShape` 弧线 + 像素化 shader | 全角色共用 |
| 命中火花 | 3 帧放射状（已有 `hit_spark` 的逻辑，替换成贴图） | 共用 |
| 落雷 | 像素闪电 3~4 帧 + 地面冲击环；加法混合只用在雷上 | 技能专属 |
| 尘土/落地 | 2~3 帧小烟尘 | 共用 |
| 死亡爆散 | 已有 `death_burst`，粒子用像素方形贴图 | 共用 |
| 格挡爆闪 | 已有 `parry_flash`，可保留矢量环 | 共用 |

**原则**：世界里的特效像素化；**贴地预警和调试面板保持矢量**（可读性优先，它们是 UI 不是美术）。
加法混合（additive）在像素风里要克制 —— 它会破坏已锁定的调色板，只留给雷、火这类发光物。

### 第一步：垂直切片（建议 1~2 周）

- [ ] `style_bible/` 定稿（参考图 + 调色板 + rules + prompts）
- [ ] 主角 112×112 基准姿势
- [ ] 主角 idle / walk / 轻击 / 跳跃 四套
- [ ] 一个敌人 idle / 起手 / 命中 / 收招

- [ ] 在 Godot 里跑通：显示 → 镜像 → 跳跃偏移 → 命中时序 → 影子
- [ ] 1× 剪影测试通过

### 代码接缝（改之前先读）

- [ ] `player.gd` / `enemy.gd` 的 `_draw()` 身体部分加 `use_sprite` 开关，保留占位作为 fallback
- [ ] `AnimatedSprite2D` 挂在角色节点下；**脚底原点**，跳跃时只动精灵层的 y
- [ ] 朝向用 `flip_h`，不生成左向素材
- [ ] `BODY_RADIUS` / `HURTBOX_RADIUS` 跟着新剪影重新调（否则「看着碰到却没中」）
- [ ] 若改角色宽度，复查边界墙的 `WALL_MARGIN` / `WALL_THICKNESS` 与自检
- [ ] 攻击/受击时长按第 3 节 Step 7 的表格重调，并 F5 复核手感
- [ ] 相机移动的亚像素抖动：先开 `snap_2d_transforms_to_pixel` 看效果，抖就关掉
- [ ] 贴地预警、调试覆盖层**保持矢量**

### 不要做的事

- 不要一次生成/绘制几十套素材再集成 —— 先跑通一套。
- 不要用 GIF（Godot 不导入；GIF 只有 1-bit alpha + 256 色）。用 PNG 精灵表。
- 不要让 AI 直接生成「整段动画序列帧」然后不修就用 —— 帧间一致性必崩。
- 不要在像素画上用平滑缩放、旋转、抗锯齿。
- 不要把预警/UI 也像素化 —— 可读性比风格纯度重要。
