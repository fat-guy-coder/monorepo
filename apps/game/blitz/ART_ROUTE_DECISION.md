# Blitz 美术路线决策：逐帧像素 vs 三渲二

> **这是一份决策辅助文档，不是承诺。** 用来把「选哪条路」的判断依据摊开，方便你慢慢斟酌。
> 选定之后，具体怎么做看 [ART_PIPELINE.md](ART_PIPELINE.md)；玩法与视角看 [DESIGN.md](DESIGN.md)。
>
> 状态：**未拍板**（决策记录见第 10 节）

---

## 0. 先给结论

**推荐：角色/敌人走「3D 预渲染成像素序列帧」，场景/道具/UI 走「手绘或 AI 像素」，即混合管线。**

理由一句话：你的目标是「一个人做一个庞大的、动作很多的像素游戏」，而逐帧像素的**边际成本永远不会下降**，3D 的会。

但**不要今天拍板**。第 7 节给了一个两周的 A/B 实验，用同一个角色、同一个动作实测，再按结果决定。

---

## 1. 先拆词：「三渲二」有两种

| 做法 | 描述 | 对现有代码的影响 |
|---|---|---|
| **实时 3D 渲像素** | 3D 场景 + 像素化 shader 实时渲染（Dead Cells 的做法） | **架构级改动**：3D 世界、相机、Y-sort、UI 全要重做。不考虑 |
| **3D 预渲染成序列帧** | Blender 正交侧视渲染 → PNG 序列 → 精灵表 | **零改动**：和像素路线一样是 `AnimatedSprite2D` |

所以真正要比较的是：

- **路线 A：手绘 / AI 逐帧像素**
- **路线 B：3D 预渲染成像素序列帧**

---

## 2. 五维对比

| 维度 | A. 逐帧像素 | B. 3D 预渲染 | 谁赢 |
|---|---|---|---|
| **首次工作量** | 低。一天就能看到画面 | 高。管线搭建 2~4 周（Blender、绑骨、渲染脚本） | **A** |
| **量产工作量** | 每角色 3~5 天，**永远不降** | 管线搭好后每敌人 1~2 天；动作、武器可复用 | **B** |
| **效果** | 手绘味强，单帧可以非常精致（Blasphemous 那种） | Dead Cells 那种：干净、可读、动作密集；但容易有「缩小的 3D 模型」感 | 看你想要哪种 |
| **精美程度上限** | **更高**。每一帧都能精雕 | 中高。受分辨率、shader、模型细节限制，但风格统一 | **A** |
| **动画连贯** | 12~24fps 的 pose-to-pose，靠手绘功力；AI 补帧容易崩 | 骨骼动画，物理正确、可混合、可 retarget；预渲染到 24~30fps 很顺 | **B，明显** |
| **风格一致性** | 靠纪律和调色板，角色越多越难 | 共享材质/光照/shader，天然统一 | **B** |
| **改动作 / 改手感** | 重画帧 | 改骨骼、重渲染，几分钟 | **B** |
| **素材体积** | 极小 | 稍大（高 fps 序列帧），几十 MB 级，可接受 | A（但可忽略） |
| **装备 / 换装** | 每套装备 = 把全部帧重画一遍（或做复杂的分层） | 换模型部件/材质，重渲染即可 | **B** |
| **后期分辨率升级** | 重画 | 提高渲染分辨率重出 | **B** |

**核心差别不在第一个角色，而在第 6 个敌人和第 30 个动作。**

---

## 3. 为什么 Blitz 特别适合路线 B

1. **固定侧视 + 朝向只有 ±1**
   3D 只需要一个正交侧机位，不用做八方向。这是 3D 管家里成本最低的一档。

2. **动作量大**
   现在就有 8 状态机 + 轻击/重击/技能/跳跃/受击/死亡/闪避。这正是骨骼动画最擅长、逐帧最不擅长的部分。

3. **v0.5 要做装备/掉落**
   这是决定性的：
   - 3D：换武器/护甲 = 换模型部件，重渲染；
   - 像素：换一套装备 = 把主角 50 帧全部重画（或搭一套分层系统，工作量也不小）。
   装备是你路线图里的核心玩法，走逐帧等于让美术成本卡住玩法。

4. **未来可扩展**
   以后想做更多敌人、更多动作、更高分辨率，3D 资产可以重渲染；像素只能重画。

## 4. 成本估算（粗糙，但方向可靠）

**假设的目标体量**：1 主角 + 8 杂兵 + 3 Boss + 3 个区域场景。

### 路线 A（逐帧像素）

| 项 | 数量 | 单价 | 小计 |
|---|---|---|---|
| 主角 | 50 帧 | 20~30 分钟/帧（AI 底图 + 手修） | 17~25h |
| 杂兵 | 8 × 36 = 288 帧 | 20~30 分钟/帧 | 96~144h |
| Boss | 3 × 60 = 180 帧 | 30~40 分钟/帧 | 90~120h |
| 场景 / UI / 特效 | —— | —— | 80~120h |
| **合计** | ~518 帧 | | **约 280~410h** |

额外成本：
- 装备系统每套外观 +20~50h（视分层方案）。
- 每次动作手感调整 = 重画相关帧。
- 角色越多，风格漂移越难控制。

### 路线 B（3D 预渲染）

| 项 | 数量 | 单价 | 小计 |
|---|---|---|---|
| 管线搭建（含学习） | 1 次 | —— | 60~100h |
| 主角 | 1 | 20~40h | 20~40h |
| 杂兵 | 8 | 11~24h（模型/绑骨/动画/渲染） | 90~190h |
| Boss | 3 | 16~30h | 50~90h |
| 场景 / UI / 特效（仍是手绘像素） | —— | —— | 80~120h |
| **合计** | | | **约 300~540h** |

额外成本：
- 首个角色慢（学习曲线），第 3 个角色之后明显变快。
- 装备换装：每套 2~4h（换模型 + 重渲染）。
- 动作调整：分钟级。

### 怎么读这两个数

- **在 8 个敌人这个体量下，总工时其实差不多。** 3D 不是「更省」，而是「**同等工时下动作更多、更好改、更好扩展**」。
- 如果你的游戏体量缩到 3~4 个敌人，路线 A 更划算。
- 如果体量涨到 15 个敌人或大量装备，路线 B 会远远领先。
- 两条路的**最大区别是风险形态**：A 的风险是「内容做不完」，B 的风险是「前期看不到东西」。

## 5. 两条路线的完整管线

### 路线 A：逐帧像素

```
风格锚 → AI 生成基准姿势 → 3 个关键姿势/动作 → 补中间帧 → 调色板统一
→ 基线对齐 → 导出精灵表 → Godot 导入 → 战斗时序对齐 → 验收
```

- 工具：Retro Diffusion / PixelLab → Aseprite 或 Pixelorama。
- 关键点：AI 只做底图和关键姿势，**每一帧都要手修**。
- 详细步骤见 [ART_PIPELINE.md](ART_PIPELINE.md) 第 3 节。

### 路线 B：3D 预渲染

```
风格锚 → 3D 模型（AI 底模 + 清理 / 现成 base mesh）
→ 自动绑骨（AccuRig / Mixamo）→ 动画（Mixamo + AI 动捕 + 手调关键帧）
→ Blender 正交侧视渲染（1× 像素密度、关闭抗锯齿）→ 调色板量化
→ 导出 PNG 序列 → 精灵表 → Godot（与像素路线完全相同）
```

- **模型**：AI 3D 人形拓扑经常不适合绑骨，预留清理时间；或直接用干净的 base mesh。
- **绑骨**：AccuRig / Mixamo 自动绑骨，省掉最枯燥的一步。
- **动画**：Mixamo 处理移动/受击；攻击用 **AI 动捕**（Rokoko Vision / DeepMotion / Plask，自己挥一段）再手调风格化关键帧。
- **渲染**：Blender 脚本，正交相机、固定侧机位、无抗锯齿、按 1× 像素密度出图。
- **统一风格**：所有角色 + 手绘场景量化到**同一套调色板**、同一左上光源，否则 3D 角色会「浮」在手绘场景上。
- **接入 Godot**：`AnimatedSprite2D` + `SpriteFrames`，和路线 A 没有区别。

## 6. 推荐方案：混合管线

| 资产类型 | 路线 | 理由 |
|---|---|---|
| 主角 / 敌人 / Boss | **B：3D 预渲染** | 动作多、要换装、要一致 |
| 场景 / 地砖 / 道具 / UI | **A：手绘或 AI 像素** | 静态资产，3D 没优势；这是定风格的地方 |
| 特效（刀光/命中/尘土） | **A：手绘像素帧** | 量小、可全角色共用、需要手绘味 |
| 贴地预警 / 调试面板 | **保持矢量** | 可读性优先，它们是 UI 不是美术 |

这个混合的原因很简单：**Blender 的时间只花在动画量最大的地方**，场景和特效继续用像素，风格锚还是由手绘资产来定。

## 8. 风险与退出条件

### 路线 A 的风险

- 内容做不完（角色/动作越多越明显）。
- 装备系统被美术成本卡死。
- AI 补帧的一致性崩，返工。
- 长期重复劳动导致倦怠。

**退出信号**：做完 2 个角色后，估算剩余内容超过 3 个月，且动作质量不稳定。

### 路线 B 的风险

- 前期 2~4 周看不到东西，容易怀疑自己。
- AI 3D 拓扑差，绑骨/清理比预期久。
- 渲染出来的像素「太 3D」，和手绘场景不搭。
- 学习成本（Blender、渲染脚本）。

**退出信号**：4 周内无法让 1 个角色 + 1 个动作在游戏里跑起来，或 1× 观感明显劣于手绘。

> **沉没成本提醒**：A/B 实验本身就是为退出准备的。两周的投入换一个可靠的决定，比闷头做三个月再发现走错要便宜得多。

## 9. 对现有代码的影响

两条路线的**接入方式完全相同**（预渲染序列帧 = 精灵表），所以这个决定**不会锁死代码**：

- [ ] `use_sprite` 开关：暂时保留 `_draw()` 占位作为 fallback
- [ ] `AnimatedSprite2D` 挂在角色节点下，**脚底原点**
- [ ] 跳跃只改精灵层的 `y = -height`，影子留地面
- [ ] 朝向用 `flip_h`，只做朝右素材
- [ ] `BODY_RADIUS` / `HURTBOX_RADIUS` 跟着新剪影重调
- [ ] 攻击/受击时长按战斗时序重调（现在的轻击 0.15s 太短，撑不住动画）
- [ ] 贴地预警/调试面板保持矢量

**不要做实时 3D-in-2D**。它会把 v0.4 好不容易定下来的坐标模型、Y-sort、相机全部推翻，收益却只是「少一次渲染导出」。

## 一句话总结

**要「单帧极致精美」→ A；要「动作多、改得快、装备能换、一个人做得完」→ B。**
你的目标里「动作多 + 装备系统 + 一个人」占了三条，所以我推荐 B + 混合管线；
但先用两周的 A/B 实验验证观感，再签字。
