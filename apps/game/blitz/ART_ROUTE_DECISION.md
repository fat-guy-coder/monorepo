# Blitz 美术路线决策：逐帧像素 vs 三渲二

> **这是一份决策辅助文档，不是承诺。** 用来把「选哪条路」的判断依据摊开，方便你慢慢斟酌。
> 选定之后，具体怎么做看 [ART_PIPELINE.md](ART_PIPELINE.md)；玩法与视角看 [DESIGN.md](DESIGN.md)。
>
> 状态：**默认方向已定为 B（3D 预渲染）**，待「最小 3D 链路」探针验证观感（2026-10-30）。
> 复核理由见 §11；决策记录见 §10；旧的 A/B 协议保留在 §7 当历史参考。

---

## 0. 先给结论

**推荐：角色/敌人走「3D 预渲染成像素序列帧」，场景/道具/UI 走「手绘或 AI 像素」，即混合管线。**

理由一句话：你的目标是「一个人做一个庞大的、动作很多的像素游戏」，而逐帧像素的**边际成本永远不会下降**，3D 的会。

但**不要今天拍板**。第 7 节给了一个两周的 A/B 实验，用同一个角色、同一个动作实测，再按结果决定。

---

## 1. 先拆词：「三渲二」有两种

| 做法 | 描述 | 对现有代码的影响 |
|---|---|---|
| **实时 3D 渲像素** | 3D 场景 + 像素化 shader 实时渲染（Dead Cells 的做法） | **架构级改动**：3D 世界、相机、Y-sort、UI 全要重做。不考虑 |
| **3D 预渲染成序列帧** | Blender 正交侧视渲染 → PNG 序列 → 精灵表 | **零改动**：和像素路线一样是 `AnimatedSprite2D` |

所以真正要比较的是：

- **路线 A：手绘 / AI 逐帧像素**
- **路线 B：3D 预渲染成像素序列帧**

---

## 2. 五维对比

| 维度 | A. 逐帧像素 | B. 3D 预渲染 | 谁赢 |
|---|---|---|---|
| **首次工作量** | 低。一天就能看到画面 | 高。管线搭建 2~4 周（Blender、绑骨、渲染脚本） | **A** |
| **量产工作量** | 每角色 3~5 天，**永远不降** | 管线搭好后每敌人 1~2 天；动作、武器可复用 | **B** |
| **效果** | 手绘味强，单帧可以非常精致（Blasphemous 那种） | Dead Cells 那种：干净、可读、动作密集；但容易有「缩小的 3D 模型」感 | 看你想要哪种 |
| **精美程度上限** | **更高**。每一帧都能精雕 | 中高。受分辨率、shader、模型细节限制，但风格统一 | **A** |
| **动画连贯** | 12~24fps 的 pose-to-pose，靠手绘功力；AI 补帧容易崩 | 骨骼动画，物理正确、可混合、可 retarget；预渲染到 24~30fps 很顺 | **B，明显** |
| **风格一致性** | 靠纪律和调色板，角色越多越难 | 共享材质/光照/shader，天然统一 | **B** |
| **改动作 / 改手感** | 重画帧 | 改骨骼、重渲染，几分钟 | **B** |
| **素材体积** | 极小 | 稍大（高 fps 序列帧），几十 MB 级，可接受 | A（但可忽略） |
| **装备 / 换装** | 每套装备 = 把全部帧重画一遍（或做复杂的分层） | 换模型部件/材质，重渲染即可 | **B** |
| **后期分辨率升级** | 重画 | 提高渲染分辨率重出 | **B** |

**核心差别不在第一个角色，而在第 6 个敌人和第 30 个动作。**

## 3. 为什么 Blitz 特别适合路线 B

1. **固定机位 + 朝向只要少数几个角度**
   3D 预渲染只需摆几个正交机位。**朝向从 v0.5 起是四向（侧 / 背 / 正），八向已砍**
   —— 这恰恰把路线 B 的优势放大了：2D 每个动作要画 3 组，
   3D 只是多渲两个机位。详见 §11.1。

2. **动作量大**
   现在就有 8 状态机 + 轻击/重击/技能/跳跃/受击/死亡/闪避。这正是骨骼动画最擅长、逐帧最不擅长的部分。

3. **v0.5 要做装备/掉落**
   这是决定性的：
   - 3D：换武器/护甲 = 换模型部件，重渲染；
   - 像素：换一套装备 = 把主角 50 帧全部重画（或搭一套分层系统，工作量也不小）。
   装备是你路线图里的核心玩法，走逐帧等于让美术成本卡住玩法。

4. **未来可扩展**
   以后想做更多敌人、更多动作、更高分辨率，3D 资产可以重渲染；像素只能重画。

## 4. 成本估算（粗糙，但方向可靠）

**假设的目标体量**：1 主角 + 8 杂兵 + 3 Boss + 3 个区域场景。

### 路线 A（逐帧像素）

| 项 | 数量 | 单价 | 小计 |
|---|---|---|---|
| 主角 | 50 帧 | 20~30 分钟/帧（AI 底图 + 手修） | 17~25h |
| 杂兵 | 8 × 36 = 288 帧 | 20~30 分钟/帧 | 96~144h |
| Boss | 3 × 60 = 180 帧 | 30~40 分钟/帧 | 90~120h |
| 场景 / UI / 特效 | —— | —— | 80~120h |
| **合计** | ~518 帧 | | **约 280~410h** |

额外成本：
- 装备系统每套外观 +20~50h（视分层方案）。
- 每次动作手感调整 = 重画相关帧。
- 角色越多，风格漂移越难控制。

### 路线 B（3D 预渲染）

| 项 | 数量 | 单价 | 小计 |
|---|---|---|---|
| 管线搭建（含学习） | 1 次 | —— | 60~100h |
| 主角 | 1 | 20~40h | 20~40h |
| 杂兵 | 8 | 11~24h（模型/绑骨/动画/渲染） | 90~190h |
| Boss | 3 | 16~30h | 50~90h |
| 场景 / UI / 特效（仍是手绘像素） | —— | —— | 80~120h |
| **合计** | | | **约 300~540h** |

额外成本：
- 首个角色慢（学习曲线），第 3 个角色之后明显变快。
- 装备换装：每套 2~4h（换模型 + 重渲染）。
- 动作调整：分钟级。

### 怎么读这两个数

- **在 8 个敌人这个体量下，总工时其实差不多。** 3D 不是「更省」，而是「**同等工时下动作更多、更好改、更好扩展**」。
- 如果你的游戏体量缩到 3~4 个敌人，路线 A 更划算。
- 如果体量涨到 15 个敌人或大量装备，路线 B 会远远领先。
- 两条路的**最大区别是风险形态**：A 的风险是「内容做不完」，B 的风险是「前期看不到东西」。

## 5. 两条路线的完整管线

### 路线 A：逐帧像素

```
风格锚 → AI 生成基准姿势 → 3 个关键姿势/动作 → 补中间帧 → 调色板统一
→ 基线对齐 → 导出精灵表 → Godot 导入 → 战斗时序对齐 → 验收
```

- 工具：Retro Diffusion / PixelLab → Aseprite 或 Pixelorama。
- 关键点：AI 只做底图和关键姿势，**每一帧都要手修**。
- 详细步骤见 [ART_PIPELINE.md](ART_PIPELINE.md) 第 3 节。

### 路线 B：3D 预渲染

```
风格锚 → 3D 模型（AI 底模 + 清理 / 现成 base mesh）
→ 自动绑骨（AccuRig / Mixamo）→ 动画（Mixamo + AI 动捕 + 手调关键帧）
→ Blender 正交侧视渲染（1× 像素密度、关闭抗锯齿）→ 调色板量化
→ 导出 PNG 序列 → 精灵表 → Godot（与像素路线完全相同）
```

- **模型**：AI 3D 人形拓扑经常不适合绑骨，预留清理时间；或直接用干净的 base mesh。
- **绑骨**：AccuRig / Mixamo 自动绑骨，省掉最枯燥的一步。
- **动画**：Mixamo 处理移动/受击；攻击用 **AI 动捕**（Rokoko Vision / DeepMotion / Plask，自己挥一段）再手调风格化关键帧。
- **渲染**：Blender 脚本，正交相机、固定侧机位、无抗锯齿、按 1× 像素密度出图。
- **统一风格**：所有角色 + 手绘场景量化到**同一套调色板**、同一左上光源，否则 3D 角色会「浮」在手绘场景上。
- **接入 Godot**：`AnimatedSprite2D` + `SpriteFrames`，和路线 A 没有区别。

## 6. 推荐方案：混合管线

### 6.1 分流判据：动作量 × 是否要和 3D 角色对齐

> 不是简单的「静态/动画」二选一。判据是两条：**动作帧数**，以及**它是否必须和 3D 角色严丝合缝**。

| 资产类型 | 路线 | 理由 |
|---|---|---|
| 主角 / 敌人 / Boss（人形） | **B：3D 预渲染** | 动作 ≥8 帧、要换装、要物理连贯 |
| 衣摆 / 披风 / 武器拖尾 | **B：3D（和角色同一场景渲染）** | 必须贴着身体，分开做一定穿帮 |
| 刀光弧线 | **A：像素独立帧** | 只要 3~5 帧，要能按元素换色、全角色复用 |
| 命中火花 / 尘土 / 落地烟 | **A：像素** | ≤4 帧、全角色共用 |
| 落雷 / 法术 | **A：像素帧 + shader** | 发光物，加法混合 |
| 场景 / 地砖 / 道具 | **A：AI 像素 + 手修** | 静态，而且这是定风格的地方 |
| 会动的场景件（火把/旗帜/门） | **A：像素 4~6 帧或 shader** | 动作量太小，3D 不划算 |
| UI / 图标 | **A：像素 + AI** | 静态 |
| 贴地预警 / 调试面板 | **保持矢量** | 可读性优先，它们是 UI 不是美术 |

**规则**：一个角色只走一条线，不要一半 3D 一半手绘；动作 ≥8 帧或需要换装 → 3D，其余 → 像素。

### 6.2 完整流程（两条支线 + 一个汇合点）

```
                ┌─ 共同前置：风格锚 ──────────────────────┐
                │  调色板 / 像素密度 1:1 / 左上光照 / 描边 │
                └───────────────┬────────────────────────┘
                                │
        ┌───────────────────────┴────────────────────────┐
        ▼                                                ▼
【3D 支线】角色 / 敌人                       【像素支线】场景 / 道具 / 特效 / UI
base mesh → 绑骨 → 动画                      AI 生成 → Aseprite 手修
→ Blender 正交渲染（1×、无 AA）               → 调色板锁定
→ 调色板量化 → PNG 序列 / 精灵表               → 导出精灵表
        │                                                │
        └───────────────────────┬────────────────────────┘
                                ▼
                      【汇合：三个统一】
                 同一调色板 · 同一像素密度 · 同一描边/光照
                                ▼
                     Godot：全部是 AnimatedSprite2D
```

**汇合点只有三件事，但缺一个就会「3D 角色浮在手绘场景上」：**

1. **同一调色板**：3D 渲染结果量化到 `palette.gpl`，否则连续色阶和像素场景对不上。
2. **同一像素密度**：角色按 112px 高渲染，1 个美术像素 = 1 个屏幕像素，不缩放。
3. **同一描边和光照**：3D 渲出来没有描边，后处理加 1px 深色轮廓；光照方向固定左上。

### 6.3 三条必须守住的纪律

1. **导出物永远可重新生成。** 真源是 `.blend` + 渲染脚本；不要手改导出的 PNG，否则改一版动作就全废了。这是「慢慢微调」成立的前提。
2. **接触阴影单独做。** 不要烘焙进角色帧 —— 跳起来时影子必须留在地面。
3. **一个角色只走一条线。** 混着做会让风格漂移，两套返工成本叠加。

### 6.4 AI / MCP / Skill 在管线里的位置

**能做（而且很值）：**

- 写和维护 Blender Python 脚本：批量导入、摆正交相机、渲染、命名、导出、生成 manifest。
- 写量化 / 描边 / 拼精灵表的脚本，保证每次输出一致。
- Blender MCP 驱动 Blender 做重复操作、检查缺失帧。
- 把整条流程包成项目 Skill，让 AI 每次按同一套参数执行。

**不能替你做：**

- 动画的力量感、节奏、pose 剪影 —— 美术判断。
- 绑骨权重质量：自动绑骨（AccuRig / Mixamo）能用，但仍要人眼检查。
- 风格锚的最终定夺。

合理分工：**AI 把可重复的部分脚本化、参数化；你负责判断和微调。**

### 6.5 落地顺序（Blitz）

1. **第 1 周**：风格锚 + 一小块像素地砖（像素支线先跑通，风格先定死）
2. **第 2~3 周**：一个 3D 角色 + idle / walk / 轻击（3D 支线脚本化跑通）
3. **第 4 周**：汇合 —— 调色板量化、描边、1× 验收，接进 Godot
4. 通过后再量产

> 先像素后 3D 的理由：**风格锚必须由像素资产来定**，3D 渲染是去「贴合」它，不是反过来。

## 8. 风险与退出条件

### 路线 A 的风险

- 内容做不完（角色/动作越多越明显）。
- 装备系统被美术成本卡死。
- AI 补帧的一致性崩，返工。
- 长期重复劳动导致倦怠。

**退出信号**：做完 2 个角色后，估算剩余内容超过 3 个月，且动作质量不稳定。

### 路线 B 的风险

- 前期 2~4 周看不到东西，容易怀疑自己。
- AI 3D 拓扑差，绑骨/清理比预期久。
- 渲染出来的像素「太 3D」，和手绘场景不搭。
- 学习成本（Blender、渲染脚本）。

**退出信号**：4 周内无法让 1 个角色 + 1 个动作在游戏里跑起来，或 1× 观感明显劣于手绘。

> **沉没成本提醒**：A/B 实验本身就是为退出准备的。两周的投入换一个可靠的决定，比闷头做三个月再发现走错要便宜得多。

## 9. 对现有代码的影响

两条路线的**接入方式完全相同**（预渲染序列帧 = 精灵表），所以这个决定**不会锁死代码**：

- [ ] `use_sprite` 开关：暂时保留 `_draw()` 占位作为 fallback
- [ ] `AnimatedSprite2D` 挂在角色节点下，**脚底原点**
- [ ] 跳跃只改精灵层的 `y = -height`，影子留地面
- [ ] 朝向：侧视用 `flip_h`（只做朝右素材），另外要有**背面 / 正面**两组；**斜向不做**（见 §11.1）
- [ ] 3D 路线下，这几组只是同一段骨骼动画渲 3 个机位，不是 3 份手工资产
- [ ] `BODY_RADIUS` / `HURTBOX_RADIUS` 跟着新剪影重调
- [ ] 攻击/受击时长按战斗时序重调（现在的轻击 0.15s 太短，撑不住动画）
- [ ] 贴地预警/调试面板保持矢量

**不要做实时 3D-in-2D**。它会把 v0.4 好不容易定下来的坐标模型、Y-sort、相机全部推翻，收益却只是「少一次渲染导出」。

## 10. 决策记录

| 日期 | 选择 | 理由 | 备注 |
|---|---|---|---|
| 2026-10-30 | **B 为默认方向**（混合管线），待 §11.3 的探针验证 | ① 朝向变四向，2D 每动作成本 ×3，3D 只多渲机位；② AI 3D 的短板（拓扑、手、脸细节）在 112px 像素化下基本被吃掉；③ Retro Diffusion 断供，2D 路的 AI 主力工具没了 | 探针没通过就退回 A，并压体量到 2~4 个敌人（见 §7 判定规则） |

## 11. 2026-10-30 复核：为什么默认转向 B

触发这次复核的两件事：
1. **v0.5 把朝向从「±1」改成了四向**（八向已在 2026-10-30 砍掉，见 §11.1 的说明）——
   §3 那条「3D 只渲染一个机位」的优势被放大了，同时 A 的成本被放大。
2. **Retro Diffusion 停服** —— 路线 A 原来的主力生成工具没了，剩下的 LiblibAI / 本地 SDXL 还没在本项目里验证过。

### 11.1 朝向数量：两条路线的成本乘数不同

同一个动作，要出几个方向，两条路线的边际成本完全不是一个量级：

| 朝向档位 | 2D 需要几组不重复素材 | 3D 需要几次渲染 |
|---|---|---|
| 单向（v0.4） | 1 组（侧视，镜像白送） | 1 个机位 |
| **四向（v0.5，已实现）** | **3 组**：侧视（+镜像）、背面、正面 | 3 个机位（侧 / 前 / 后，正交相机转一下） |
| ~~八向~~ | ~~5 组~~ | —— **不做**（2026-10-30 决定，见下） |

- 2D 的「一组」= 该动作的全部帧重画一遍，工作量约等于第一次的 50~80%（同角色有参考，但每一帧都得过手）。
- 3D 的「一个机位」= 相机转 90° 再跑一次渲染，**秒级，且和原机位必然一致**（同一段骨骼动画）。

> 也就是说：**四向这个玩法决定，本身就在给路线 B 加票。**
> 2D 能省的那点「首次工作量」，在第二个动作、第三个方向就已经还回去了。

**为什么砍掉八向（斜向 45°）**：不是美术扛不住，是**玩法上 4 轴更清楚**——
`AttackShape` 本来就从 `facing` 生成，只有 4 个朝向；加斜向要让吸附表、形状朝向、测试矩阵一起变，
而格挡的 `(受击方向 · 朝向) >= 0` 半平面会退化成 90° 锥，「挡没挡住」变模糊。
DNF / 怒之铁拳 4 / 龙之皇冠都是这个做法。代价只是斜走时的 45° 滑步观感，
靠 `Facing.choose` 的 1.25 迟滞 + 出招锁朝向压住。
若真的走 3D 路线，斜向只是「相机多转 45°」，那时想加再加，判定层不用动。

### 11.2 AI 3D 现在到了什么程度（用之前要知道的部分）

据 2026 年的公开对比实测（见文末来源；这些多为厂商/SEO 站，具体版本号当参考不当事实）：

**明显变好的部分：**
- **单图/多视图 → 带纹理网格**的视觉质量已经够用，做风格化角色没问题。
- **拓扑**：Tripo 开始出四边面（P2.0 Preview，约 0.5k~25k quads），Hunyuan3D 的拓扑被评「最干净、不用手工清」，Meshy 有 Smart Topology。
- **绑骨/动画**：Meshy 内置自动绑骨 + 数百条预设动作；Tripo 有自动绑骨，骨架兼容 Mixamo。单图直接产出「网格 + 骨骼 + 蒙皮」的研究路线也已出现。

**仍然要用人的部分：**
- **重拓扑与绑定的顺序**：先绑后 remesh 会把骨架数据冲掉 —— 顺序错了要返工，这是最常见的坑。
- **手和脸**：AI 模型依旧容易崩。但注意 —— 按 Blitz 的 112px 画布，**手大概 1~2 像素、脸 4~5 像素**，这个尺度上崩掉的手根本没地方显示。
- **动画质量**：自动动作普遍「软、飘」，出手时机、预备动作、打击停顿还是手调曲线。

> **像素化是 AI 3D 的天然降噪器。** 这条是核心：AI 3D 的瑕疵集中在细节和拓扑，而像素化恰恰是把细节抹平的那一步；
> 反过来说，AI 2D 像素的瑕疵是**每一帧都摆在你面前**的 —— 两张图之间差一条边、多一像素的高光，玩家一眼就看出来。
> 所以「用 AI 3D 做像素」比「用 AI 直接做像素」对 AI 更宽容。

### 11.3 先跑「最小 3D 链路」探针，别直接量产

§7 那个两周 A/B 现在不划算了（A 的工具链刚断供，两边不对称）。改成 **2~3 天的一条竖切**：

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 | 拿已有锚图 `art/export/probe/anchor_side_2001.png` 或 `turnaround_3001_a.png` | 输入 |
| 2 | Tripo / Meshy 出模型 → 自动绑骨（Meshy 更省事，Tripo 网格更好） | `.glb` |
| 3 | Mixamo 或预设动画：idle + 一次挥击 | 骨骼动画 |
| 4 | Blender 正交相机渲 4 个机位（侧/背/正/斜），无 AA、透明背景、1× | PNG 序列 |
| 5 | `art/tools/palette_quantize.py` 量化到 `style_bible/palette.gpl` + 1px 描边 | 可入游戏的帧 |
| 6 | 在 Godot 里按 32px 地砖摆上去，截图看 1× 观感 | 判定材料 |

**判定（对着现在的 2D 试产图看）：**
- 1× 下侧视剪影读得出来、三个方向能一眼区分、挥击有重量感 → **走 B**，开始量产。
- 只是「不丑但没劲」→ 是动画曲线问题，不是路线问题，继续 B 但补动画功夫。
- 明显劣于 2D 且改不动 → 退回 A，体量压到 2~4 个敌人。

## 12. 技能主导下的资产分工（2026-10-30）

玩法定位改成 **「技能主导、动作为辅」** 之后（见 [DESIGN.md](DESIGN.md)「玩法重心」一节），
美术预算的重心整体挪了位置。结论不变、但理由变了：

### 12.1 为什么重心挪了

| | 动作主导（原设想） | **技能主导（现定位）** |
|---|---|---|
| 玩家花时间在哪 | 招式对拆、帧级博弈 | 选技能、走位、躲预警、放连招 |
| 美术吃工在哪 | **角色的攻击帧**（长连段 × 多招式） | **技能表现**（VFX、预警、命中反馈） |
| 角色动作帧 | 每个招式 8~16 帧，还要接得上 | **短**：起手 3~5 帧 + 收势即可，中间靠特效 |
| 能用程序化解决的部分 | 少 | **多**（投射物、AOE 圈、光束、弹幕都能 shader 派生） |

> 一句话：**技能多 ≠ 角色动画多，只 ≠ VFX 多。而 VFX 是 2D 像素 + shader 最擅长、也最能复用的东西。**
> 所以 2D 在你项目里的比重没有变小，只是从「角色帧」挪到了「特效帧」。

### 12.2 分工表（最终版）

| 资产 | 路线 | 理由 |
|---|---|---|
| 玩家 / 小兵 / Boss 的**身体** | **3D 预渲染**，3 个机位（侧 / 背 / 正） | 数量多、要换装、要改动作；2D 每个方向都得重画 |
| 技能的**角色姿态** | 同一套骨骼的短 clip（3~5 帧量级） | 不单独做美术，重渲染即可 |
| **技能特效 / 投射物 / AOE / 弹幕** | **2D 像素 + shader + 粒子（程序化）** | 主要工作量，也是「精美」的来源；一个系统派生几十个技能 |
| 命中反馈（火花 / 顿帧 / 屏震 / 数字） | 2D，全局共用 | 全角色复用，做厚收益最高 |
| 场景 / 地砖 / 道具 / UI | 2D（AI 底图 + 手修） | 定风格的地方 |
| 预警 / 调试面板 | **保持矢量** | 可读性优先，它们是 UI 不是美术 |

### 12.3 Boss 是决定性的那一步

算一下就知道为什么：

| | 2D 逐帧 | 3D 预渲染 |
|---|---|---|
| 一个 Boss，6 个技能 × 3 个朝向 | 6 × 3 × 8 帧 = **144 帧手工** | 6 个 clip，每个渲 3 次 = **18 次渲染** |
| 3 个 Boss | ~432 帧 ≈ 200~300h | 3 个模型 + 18 个 clip ≈ 150~250h（含学习） |
| 加一个 Boss | 从零重画 | 换模型，**动作可 retarget 复用** |
| 改一次出招时机 | 重画相关帧 | 调曲线，几分钟 |
| Boss 体型大（192px） | 每帧像素更多，更贵 | **和体型无关** |

Boss 越多、技能组越复杂，3D 的优势越大 —— 这正好对上你说的「Boss 的技能和动作组要做多点」。

### 12.4 AI 生成序列帧现在能用到哪（诚实版）

| 用途 | AI 序列帧现状 | 结论 |
|---|---|---|
| 场景循环（火把 / 旗帜 / 水面 / 雨） | 4~6 帧，逐帧检查就能用 | ✅ **用** |
| 技能特效的关键帧 | 单帧底图可用，中间帧靠手排 + shader | ⚠️ 只出关键帧，别出整段 |
| 角色 idle / walk 循环 | 勉强（试产 6 帧里坏了 1 帧） | ⚠️ 能试，必须逐帧验 |
| **角色攻击 / Boss 技能组** | **不可靠** | ❌ **不用** |

理由不是「画得丑」，是**帧间一致性的崩坏点正好落在关键帧上**：

- 动作幅度越大，帧与帧之间的衣服、武器位置、身体朝向漂得越多；
- 坏的那一帧往往就是**命中帧**（剑在哪、朝向对不对）—— 而这正是玩家唯一会盯着看的帧；
- 修一帧的时间 ≈ 做一个 3D clip 的 1/3，而且**下一版改动还要再来一遍**。

> 一句话：**AI 序列帧适合「数量少、动作慢、不需要方向一致」的东西。
> Boss 技能组是这三条的完全反面。**

### 12.5 成本真相（别被「3D 更省」误导）

3D 不是免费。一个 Boss 仍然要 20~40h（模型 → 绑骨 → 6 个动作 → 3 机位渲染 → 量化描边 → 接入）。
8 个 Boss ≈ 200~300h。

但两者风险形态不同：

- **2D 是超线性**：每个新方向、每个新技能都从零画，体量一涨就崩。
- **3D 是线性且可预测**：每加一个 Boss 是固定成本，改动作几乎免费，**内容做不完的风险小得多**。

在这一步之前，先跑 §11.3 的最小链路探针 —— 它同时也是 3D 管线「到底多少钱一小时」的实测。

## 一句话总结

**要「单帧极致精美」→ A；要「动作多、改得快、装备能换、一个人做得完」→ B。**
你的目标里「动作多 + 装备系统 + 一个人」占了三条，所以我推荐 B + 混合管线；
但先用两周的 A/B 实验验证观感，再签字。
